# 実バックアップに向けたオフライン保管ツール

Node 24.22.1の標準機能だけで、管理者が別途用意したファイル一式を暗号化・復号します。
DBへの接続・ダンプ取得・クラウドへのアップロード・古いバックアップの削除は行いません。
本番データの取得は保管方針の承認後に別作業として実施します。

## 準備と実行

Git管理外の作業場所に、入力フォルダと保存先の親フォルダを用意します。
POSIXでは保存先の親フォルダを所有者のみ利用できる0700にします。鍵は24バイト以上・1024バイト以内。
以下の`/private/...`は例示です。実在する、権限を確認したパスに置き換えてください。
鍵を引数・環境変数・コマンド履歴へ直接記入せず、別管理の秘密ファイル等をfd 3へ渡します。

```bash
node tools/backup-kit/backup.mjs seal /private/input /private/backups/backup-20261104T000000Z.spbk 3</separately-managed/key
node tools/backup-kit/backup.mjs restore /private/backups/backup-20261104T000000Z.spbk /private/restore/new 3</separately-managed/key
node tools/backup-kit/backup.mjs retention-plan /private/backups 30
```

`seal`はファイル名・長さ・SHA256の目録も暗号化します。AES-256-GCM、ランダムsalt/nonce、scrypt N32768/r8/p1を使用。
ストリーム処理で大きいファイルもメモリーへ丸ごと読み込みません。入力は取得完了した静止コピーを使ってください。
暗号化前後のハッシュで入力変更を検出しますが、DBとStorageの一貫したスナップショット取得までは担当しません。
暗号化先は既存ファイルを上書きせず、Git管理下・入力フォルダ内・シンボリックリンクの入力を拒否します。
復号は所有者限定の一時領域へ行い、認証タグが確認できるまでファイルを展開しません。
パス移動・重複名・不一致サイズ・内容ハッシュの異常を拒否します。失敗時は一時領域を除去します。
復元先は存在しないディレクトリだけを受け付け、既存ファイルを置き換えません。

`retention-plan`は指定日数より古い`backup-YYYYMMDDTHHMMSSZ.spbk`名のファイルだけを候補として表示します。
これはmtimeによる保守候補であり、復元成功・法定保存・最後の正常コピーを判断しません。**削除機能はありません。**
実在する名前が候補に含まれるため、この出力も公開GitHubに保存しないでください。

## 受け入れ確認

```bash
node --test tests/backup-kit.test.cjs
```

架空のバイナリー・空・日本語名・2MiBファイル、誤鍵、改ざん、切断、上書き拒否、リンク拒否、保存期間の非削除を確認。
認証済みの不正目録や極端なサイズも別の境界テストで拒否を確認します。

## 管理者に残る責任

- 鍵と暗号文の権限を別々に管理し、復旧担当者が鍵を受け取れることを確認する。
- バックアップ元へDB・Auth・Storage本体・設定を揃え、件数/ハッシュと取得期間を記録する。
- 保存容量を確認し、実復元まで確認した正常コピーを維持する。
- 一時ファイルは通常削除であり、安全消去は保証しない。暗号化ディスク上で作業する。
- POSIXの権限検査だけではクラウド共有設定やWindows ACLを確認できない。別途確認する。
- 実バックアップの取得・非公開先への転送・DB復元の実行は未実施。
