## 変更した動作

- 応募・応募キャンセルは、同じ操作/対象の処理中の再送を抑える。失敗/確認取消後は再試行できる。
- 応募時に求人が消えていた場合は例外にせず案内する。重複エラーはSQLSTATE 23505も判別する。
- 通信例外では成功と表示せず「完了を確認できない」と案内する。書込後に応答だけ失われた可能性があるため、応募履歴の確認を促す。
- 企業・ドライバー双方の退会で処理中の重複呼出しを抑え、通信例外を案内する。
- 退会APIから明示的にok:trueを受け取った後は、ローカルのサインアウトが例外になっても退会成功の案内とホームへの遷移を続ける。
- 退会拒否・認証切れ・未確認の応答では、成功表示・サインアウト・画面遷移を行わない。

この抑止は同じタブの実行中だけ。別タブ・別端末・再読み込み・応答喪失後の再送を保証する仕組みではない。
DBの一意制約・認可・記録保持ガード等は引き続き必要。本番適用の順序は[レビュー計画](v4-release-review-plan.md)に従う。
