## 新たに見つかったこと

### 新環境の既定権限が復元対象へ混ざる

pg_restoreを行っただけでは、新環境のオブジェクト作成者のdefault ACLが追加され、取得元と権限が一致しなかった。
[新規fixtureだけの整理SQL](../../tools/native-runner/reset-fixture-default-acl.sql)をアプリ構築前に実行し、その後にダンプ内の権限を復元する。
[詳細照合SQL](../../tools/native-runner/read-security-catalog.sql)で非公開関数/列/採番/Authトリガーまで比較する。
既存の本番でこの整理SQLを実行する手順ではない。

### 画面側の人数確認だけでは同時採用を防げない

別ドライバー2人を同時採用すると、required_headcount=1でも2件を確定できた。
[DB制限案](../../sql/review-v4-hiring-capacity.sql)は対象求人をロックして人数を再計算し、超過と採用済み人数以下への定員縮小を止める。
[切り戻し案](../../sql/review-v4-hiring-capacity-rollback.sql)もレビュー専用。制限解除は定員超過を再び許すため先に採用処理を止める。
本番には適用していない。

## この16項目に含めない承認・人の作業

実データ保管の鍵/保持/復旧目標、受取人本人の実演・権限/MFA移管、本番への反映、実機カメラ/生体認証と実メール・LINE配信。
別クラスタでも同じホスト内の架空データ検証であり、別クラウドへの実データ完全移行ではない。
Storage object UUID・作成時刻・旧署名URL・外部契約や鍵の移管は自動的には再現しない。
