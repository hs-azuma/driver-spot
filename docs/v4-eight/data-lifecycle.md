# 保存・退会・匿名化の運用案（決定待ち）

これは担当者が運用を決定するための案です。保存年数の決定・本番データ削除・法的適合の確定は含みません。
現行の退会ガードは、業務記録やStorage所有物が残るユーザーの自動退会を拒否します。
退会依頼と、会計・勤怠等の記録削除を同じ処理にしません。

| 区分 | 主な対象 | 保存方針の決定者 | 削除・匿名化の前提 |
|---|---|---|---|
| アカウント・プロフィール | Auth、drivers、companies、account_login_ids | 所有者・運用担当 | 本人確認、業務記録/所有ファイル/紛争の確認、セッションの扱い |
| 業務履歴 | jobs、applications、attendance_review_requests、attendance_edit_logs | 業務・経理・労務担当 | 必要な記録の保全、保持期間の確定、関連データと監査証跡 |
| 連絡・関係情報 | 通知キュー、LINE連携、お気に入り、ブロック、招待 | 運用担当 | 配信停止、実行中ワーカーと再試行の確認、関連行の扱い |
| 認証・不正対策 | 復旧コード、認証試行制限、認証/操作ログ | セキュリティ担当 | 不正調査の保留、復旧アクセスと管理権限の維持 |
| ファイル | Storageの各bucketと実体 | 運用担当・所有者 | ファイル種類、所有者、業務証跡、旧URL参照の確認 |
| バックアップ | DB/Auth/Storageの暗号文と設定 | 鍵管理者・保管担当 | 保存期間、最後の復元成功コピー、法的保留、鍵の管理 |

## 決定票

各区分について、保管目的、対象項目、保存開始の基準日、保存日数、例外・保留条件、閲覧権限、実行者、承認者を記入します。
日数は未決定です。法務・経理・労務の確認が必要な期間を推測で埋めません。
承認済みでない区分や対象時点が不明なデータは処理対象にしません。

## 依頼を受けてから完了するまで

1. 依頼者本人と対象範囲を確認し、依頼番号を非公開の管理台帳へ記録する。
2. 新規通知・外部連携・セッション継続の扱いを確認し、停止する対象を承認する。
3. 既存のwithdrawal_preflight等で保持理由を確認する。業務履歴やStorageが残る場合は自動削除を強行しない。
4. 保持が必要なデータと匿名化可能な項目を担当者が判断する。外部キーを壊す削除や一括置換をしない。
5. 非公開の作業環境で対象件数をdry runし、関連記録・バックアップを含む方針を承認する。
6. 実行後は対象件数・結果・実行者・時刻・例外を記録し、不要になった作業用データを除去する。
7. バックアップから復元した場合、復元後に未反映の退会/配信停止依頼を再適用してから通知を再開する。

## バックアップと削除依頼

通常運用のバックアップから特定行を即時に抜き取れるとは限りません。
承認された保存周期・アクセス制限と、復元時の再適用台帳を組み合わせる案を担当者が確認します。
この文書だけを根拠に保管を延長したり、本人への回答内容を確定したりしません。

## 完了条件

担当者と保存日数が確定し、例外を含むdry run・復元後再適用・本人への回答手順を実例で受け入れた時点で運用開始とします。
