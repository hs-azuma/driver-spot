# 本番適用前の変更しない診断

[predeploy-read-only.sql](../database/predeploy-read-only.sql)はREAD ONLYトランザクションとタイムアウトを使い、集計件数だけを返します。
権限のない閲覧者の結果はRLSによって一部行しか見えない可能性があります。全件診断は承認済みの監査用権限で担当者が行います。
空の隔離環境にアプリDDL・レビュー案を適用して先に検証します。本番への接続と実行は今回の対象外です。

## 診断対象

- PG majorとテーブル数、RLS、未検証制約・無効インデックス。
- 定員超過、無効な定員、応募の参照先不在、重複応募。
- 出勤なしの退勤、時刻の逆転。
- 採用定員ガードの有無、匿名ユーザーから実行可能な権限付き関数。

公開SECURITY DEFINER関数には意図的なAPIもあります。件数だけで一律に権限を剥奪しません。
関数定義の認可チェックと既存の実行権限台帳を照合して判断します。

取得結果をJSONだけの非公開ファイルに保存し、オフラインで以下へ渡します。

```bash
python3 -B scripts/check-predeploy.py < /private/preflight.json
```

不明値・異常・ガード未適用はREVIEW_REQUIREDです。PASS_LOCAL_PREFLIGHT_ONLYでも本番適用承認にはなりません。
診断では採用取消・定員変更・削除を行いません。既存の超過案件は業務担当者が当事者への対応を決めます。
READ ONLYは無負荷を意味しません。大きいDBではタイムアウトの可能性があります。自動再試行せず、実行計画と負荷を別途確認します。
