# ログインIDによる登録（2026-10-06）

新規登録はログインIDとパスワードで即時ログイン。メールは通知先として任意。従来のメールアドレスによるログインは維持する。ドライバーの氏名・カタカナ・電話番号は必須、勤務地は任意。企業は会社名が必須。

account-auth Edge Function がログインIDをサービス専用テーブルで管理する。メールなしのAuthレコードにはランダムな予約ドメインの内部識別子を使用する。UI・プロフィール・メール通知では内部識別子を除外する。新規登録だけ管理APIで確認済みユーザーを作成し、既存のSMTP・メール認証設定は変更しない。

復旧コードは192ビットの乱数。ハッシュだけを保存し、使用時にコードを交換する。再発行・通知メール変更には現在のパスワードが必要。復旧コードとパスキーの両方を失うと自動復旧できないため、登録後に保存確認を表示する。

パスキーはSupabaseネイティブWebAuthn（supabase-js 2.105.0）を利用する。RP IDはspodora.com、許可Originはhttps://spodora.comとhttps://www.spodora.com。対応する安全な接続の端末だけ設定・ログインボタンを表示する。実端末のFace ID・指紋操作は端末所有者が行う。

SQLはaccount-login-ids.sqlとaccount-notification-email-guard.sql。新しいサービス専用テーブルはRLS有効、anon/authenticatedの権限なし。登録・ログイン・復旧に回数制限を設ける。新規登録のボット対策強化は利用状況に応じて検討する。

## 検証

- 本番の使い捨てテストアカウントでメールなし登録、ログイン、誤パスワード拒否、ID重複拒否、復旧コードによるパスワード変更・旧コード拒否を確認。
- 企業のメールなし登録、現在のパスワードによる通知メール変更、ID継続、コード再発行を確認。
- 未ログインの設定API拒否、許可外Origin拒否、内部アドレス除外を確認。
- ヘルパー単体検証: node --test tests/account-auth-helper.test.cjs。
- 全変更HTMLのインラインJavaScript構文検証。
- 本番画面の必須・任意表示と公開Auth設定passkeys_enabledを確認。
- テストでメール・LINEを送信していない。テストアカウントは削除する。
