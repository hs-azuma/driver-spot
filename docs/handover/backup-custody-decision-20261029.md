# 実バックアップ開始前の決定票

状態: 保管先の空フォルダのみ準備済み。実データ未取得、鍵未生成、実復旧未確認。

## 具体的な準備案

- 保存先: 既存Google Drive内のスポドラ専用フォルダを作成し、共有なし・所有者のみを確認した。
- 正確なフォルダ参照は所有者へのチャットだけで案内し、公開GitHubへ置かない。
- DB/Auth/Storage/Functions/外部設定の範囲を一覧化し、保存できない対象を欠落として記録する。
- 公開GitHub・Actionsログ・Actions成果物には実データも鍵も置かない。
- 暗号化したバックアップと復号鍵のアクセスを分離し、受取人本人が復号できるまで復旧可能とはしない。
- まず架空データで経路と復号/復元を検査し、その後に実データの取得範囲を確定する。

## 所有者の指定が必要な項目

|項目|現在|決める内容|
|---|---|---|
|復号鍵の管理者|未定|本人氏名/役割、主担当不在時の予備管理者|
|鍵の保管場所|未定|バックアップと別のアクセス経路。誰が本人確認して渡すか|
|保持・削除|未定|保持期間、世代数、廃棄確認。法定期間をここで決めない|
|復旧目標|未定|どの時点まで戻すか、許容する欠損と停止時間|
|実データ取得/復旧担当|未定|最小権限の一時アクセスと作業記録|
|第三者の受取人|未定|担当者別アカウント/本人確認/実演日|

空欄をこちらで人物へ割り当てたり、秘密値をチャットに貼ることを求めたりしない。
鍵管理者と鍵の受け渡し方法が未確定のため、復号できない暗号化データを先に作って保存しない。
実データの取得権限・接続方式は、対象/鍵/保持を確定してから最小権限で用意する。
Supabaseの本番設定・課金・保存プランは今回変更しない。
