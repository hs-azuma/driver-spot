# バックアップ・復元・運用の決定案

2026-11-06（日本時間）。F07〜F11の実行準備。状態は決裁待ち。既存の[決定票](backup-custody-decision-20261029.md)と[保管計画](../backup-recovery-plan.json)の承認値は空欄を維持する。

| 決定事項 | 提案 | 実行前の確認 |
|---|---|---|
| 取得頻度 | 1日1回と重要変更の直前 | 実行担当・代行担当と実行ホストを指定 |
| バックアップ保持 | 日次30世代・30日を初期案とする | 業務記録自体の保存期間は区分別に別途決裁 |
| 許容するデータ損失 | 最大24時間を目標 | この損失を許容できるか業務側が決裁 |
| 復旧時間 | 8時間以内を初期目標とする | 初回復元で実測し、目標未達なら手順・時間を見直す |
| 保管容量 | 日次30世代・変更前コピー・作業領域の合計容量を見積る | 実測サイズ・既存容量を確認し、無料範囲を超えるときは作業を保留 |
| 保管先 | 以前用意した所有者のみの既存Driveフォルダ | 現在も非共有・ownerのみ・空であることを読取確認済み |
| 復号鍵 | 暗号文と別の権限・経路で保管 | 鍵管理者・代行者・既存の保管場所を指定 |
| 実行権限 | 取得・復元・保管を最小権限で実施 | 誰が取得し、誰が復号・復元するかを記入 |
| 最初の実バックアップ | 承認範囲のDB/Auth/Storage/Functions・外部設定 | 保存できない対象と秘密値の受渡し経路を明記 |

## 実施順序

1. 鍵管理者と受渡し手順、実行担当、取得範囲、保持・復旧目標を決裁する。
2. 非公開の取得先・作業領域を確認し、DB/Auth・設定の取得完了を記録する。Storageは現在本体0件という観測を、実施時にも確認する。
3. 既存backup-kitで暗号化し、入力ファイルのハッシュと暗号文の整合を確認する。
4. 非公開保管先への保存を読み戻して確認し、暗号文と鍵のアクセス分離を確認する。
5. 通知・cron・外部フックを停止した隔離先へ復元する。実データを公開GitHubランナーへ持ち込まない。
6. 本人ログイン、権限拒否、採番、行・ファイル・カタログと設定の欠落を照合し、時間を記録する。
7. バックアップ後の退会・配信停止依頼を非公開台帳から再適用し、再実行時に重複しないことを確認してから再開判定する。
8. 取得失敗・保管失敗・復号失敗・照合不一致では直前の正常コピーを保持し、担当へエスカレーションする。
9. 初回の成功後に日次取得、月次の復元訓練案、世代整理の実行日を決める。削除候補の表示と実削除の承認を分ける。

この案に人名や秘密値は記入していない。鍵生成・実データ取得・保存・復元・定期処理の登録は、各条件が確定した後に実施する。
