# 未確認勤務・欠勤・取消の決定案

2026-11-06（日本時間）。F27の判断資料。運用責任者による決裁待ち。

## 案A 既存表示と非公開の確認台帳を使う初期運用

既存の「出勤未確認」「勤務実績未確認（要確認）」「退勤未確認」を起点に、受入企業の勤務管理担当が事実を確認する案を推奨する。
台帳には勤務ID、申告した側、確認担当、確認時刻、理由、本人への確認状況、取消・訂正の前後、次の対応を記録する。
担当者本人の氏名は受入企業が指定し、運営窓口と代行者も決裁欄に記録する。

| 状態 | 確認する事項 | 記録と次の対応 |
|---|---|---|
| 打刻がない | 実際の勤務有無、端末・通信・QRの事情 | 未確認のまま給与を確定せず、事実確認後に既存の勤怠修正・承認へ進む |
| 出勤後に退勤なし | 実際の終了時刻、休憩、連絡状況 | 本人申請と企業確認を通して修正し、根拠を保存 |
| 欠勤申告 | 本人・企業双方の認識、勤務日、連絡時刻、理由 | 誰がいつ確認して欠勤と判断したかを記録。表示と支払判断の扱いを決裁 |
| 企業側の取消 | 取消時刻、理由、本人への連絡、既に勤務・契約があるか | 取消前の条件と履歴を保持し、給与・交通費等は労務の確認結果に従って判断 |
| 確定後の訂正 | 元の判断、訂正理由、相手方の確認 | 元記録を残して追記し、集計・CSV・連絡への反映を照合 |

この案では欠勤という新しいDB状態を追加する実装範囲を決裁せず、初期運用の記録方法を先に確定する。
実装を求める場合は、本人・企業・運営の権限、並行更新、二重操作、変更履歴、再申請、月次・CSVへの影響を個別の変更範囲にする。
