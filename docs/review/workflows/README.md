# 旧自動書き換え処理の停止・固定案

現在の2ファイルは変更していません。以下はレビュー専用の候補で、GitHub Actionsとして実行されません。

| 対象 | 現行の問題 | 候補の動作 |
|---|---|---|
| rebrand-spodora.yml | ファイル変更pushから起動し、driver.htmlへ旧文字列置換を適用してpush | 手動の読み取り点検だけ。自動起動・push・書き込み権限を除去 |
| update-driver-experience.yml | mainのpushでindex.htmlを置換し再push。現在の画面と競合する可能性 | 同上 |

両候補はcheckoutのコミットを固定し、標準ubuntu-24.04・3分の上限・資格情報を保存しない構成です。
本番用workflowの変更・停止は、影響を示して承認後に行います。依存台帳の`unfixed_action_refs: 2`は現行ファイルについて正しく残します。

## 承認後の適用手順

1. mainの最新SHAと元workflow2件の内容を取得し、このpatchの前提と一致するか確認する。
2. 本候補と差分をレビューし、2件の自動書き換えが不要であることを運用責任者が確認する。
3. 独立した変更として候補を配置する。rebrandの現行push条件は自身の変更でも起動し得るため、変更後が手動条件であることを確認する。
4. 現行の実行中ジョブや待機ジョブがないか確認し、残っている場合は承認した担当者が扱う。
5. 変更後の権限と起動条件を読み戻し、main/Pagesへ意図しない追加コミットがないか確認する。

切り戻しは旧workflowを無条件で復活させず、必要な作業を新しいレビュー済みソース変更で実施することを優先します。
旧workflow自体を戻す場合は再び書き換えが起こるため、別途承認と最新画面の差分確認が必要です。
