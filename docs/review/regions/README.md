# 保存済み地域の選択と通知範囲のレビュー

2026-11-06（日本時間）。F26の追加調査。候補のareas.jsと本番には未適用。

## 再現した問題と修正案

現在のareas.jsでは、保存済みの市区町村が選択肢にない場合、編集画面のselectで先頭の都道府県全域が選択される。
例えば「東京都／新宿区」を読み込むと「東京都全域」になる。同じ画面を保存すると、利用者が選んでいた地域を広げるおそれがある。

[修正候補](fill-municipality-candidate.js)は、保存済み値を選択肢に追加して選択状態を保持する。
Option要素で表示するため、保存済み値にHTML記号が含まれていてもテキストとして扱う。
既存の市・集約地域・全域の選択値、未入力時の既存動作も保持する。

[差分](areas-preserve-selection.patch)はareas.jsだけを対象とする。`git apply --check docs/review/regions/areas-preserve-selection.patch`で現在のソースに適用可能なことを確認した。
本番適用には別途承認が必要。

## 実ブラウザーでの検証

`node tools/business-lab/region-browser.mjs`で実際のareas.jsを読み込み、現行の選択変更を再現してからレビュー候補を同じ隔離ページに読み込む。
新宿区、既存の東京都23区、大阪市、都道府県全域、一覧外の保存地域、HTML記号を含む保存値、未入力を含む10チェック成功。
[結果とソースハッシュ](browser-result-20261106.json)を保存した。プロフィールの保存、データ移行、実通知は実行していない。

## 集約地域と個別地域の通知について

今回の選択保持案は、現行の完全一致・都道府県全域による通知判定を変更しない。
「東京都23区」と「新宿区」の包含関係を通知に導入する場合は、次の対応表案を画面・メール・LINE・DBで共有して検証する。

| 希望地域 | 求人地域 | 対応案 |
|---|---|---|
| 東京都全域 | 東京都内の個別地域・東京都23区 | 対象 |
| 東京都23区 | 23区の個別区名 | 対象 |
| 新宿区 | 新宿区 | 対象 |
| 新宿区 | 東京都23区 | 詳細勤務地を確認するまで自動では対象を広げない |
| 東京都23区 | 東京都内の市・町・村 | 対象外 |
| 他の都道府県の同名地域 | 東京都の地域 | 対象外 |

東京都の公式一覧で、23区と市・町・村が分けて掲載され、新宿区が23区に含まれることを確認した。
[東京都の区市町村一覧](https://www.sports-tokyo-info.metro.tokyo.lg.jp/wardsTop.html)

対応案の受入時には希望勤務地1〜3、全域、通知ON/OFF、休会、ブロックと解除、再送抑止を同じ表で確認する。
公式一覧と照合した現在の入力データは47都道府県・個別選択肢282件で、全市区町村を収録したものとして扱うには追加整備が必要。
希望条件の意味と、集約された求人の実際の勤務地を確定した上で、対象地域の追加と既存値の扱いを決める。
